# apidex

An MCP server that gives coding agents a **verified directory of public APIs**.

**Browse the directory:** https://memfactorduke.github.io/apidex/

Agents hallucinate APIs constantly — dead endpoints, invented auth schemes, imaginary rate
limits. apidex fixes that: every entry in its dataset was researched and then **cross-checked
by two independent verification passes** (plus automated liveness checks), with disagreements
settled by a third adjudication pass. The verification record ships with each entry, so your
agent can see exactly which fields were confirmed.

## Install

**Claude Code**

```sh
claude mcp add apidex -- npx -y apidex
```

**Codex CLI**

```sh
codex mcp add apidex -- npx -y apidex
```

**Any other MCP client** (stdio transport):

```json
{ "mcpServers": { "apidex": { "command": "npx", "args": ["-y", "apidex"] } } }
```

No API key, no network calls, no telemetry — the dataset is bundled and everything runs
locally.

## What your agent gets

| Tool | Purpose |
| --- | --- |
| `find_api_for_task` | "convert an address to coordinates, free, no API key" → best-matching verified APIs |
| `search_apis` | Keyword search with filters: category, `free_only`, `no_auth_only`, `cors_only` |
| `get_api` | Full record: base URL, auth, free-tier limits, rate limits, CORS, a working example `curl`, docs link, verification record |
| `list_categories` | Categories with counts and dataset stats |

Typical agent flow: `find_api_for_task` → pick a result → `get_api` → copy the verified
example request instead of guessing one.

## Why trust the data

Each entry went through a multi-stage pipeline:

1. **Research** — an agent with live web search fills a strict JSON schema from official docs.
2. **Machine checks** — scripted liveness checks on every base/docs URL, schema validation.
3. **Double verification** — two independent agents (one docs-first, one adversarial)
   re-research every entry and issue per-field verdicts: `confirm` / `incorrect` /
   `unverifiable`. Nothing is "confirmed" that wasn't actually checked.
4. **Adjudication** — any disputed field goes to a third agent that rules with sources.

Entries that failed verification or turned out defunct were dropped, not shipped. The
`verification` block on every entry lists which fields were confirmed by both verifiers,
which were corrected, and which remain unverifiable (e.g. unpublished rate limits).

**Dataset stats** (2026-08-08 build): 462 APIs across 21 categories — 427 with a free tier,
121 requiring no auth at all, 13 with CORS confirmed for browser use. The verification
machine earned its keep: adjudication applied **790 field-level corrections** after the
dual-verify stage, and the cross-family audit round (offline GPT-5.6 flags disputes, a
live-web agent arbitrates each one against current official docs) corrected **1,934 more
field values** across 348 audited entries — pricing drift, renamed endpoints, stale rate
limits. 17 candidate APIs turned out to be dead or decommissioned and were dropped. A
single-pass dataset would have shipped every one of those errors.
